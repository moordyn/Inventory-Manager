# Inventory Manager v1.2.0 — Account management and deployment improvements

**Release type:** Minor feature release, following v1.1.0. This release includes email-change verification, role-aware employee display-name editing, global-admin employee ID updates, original owner ID renaming, a configurable `--domain` installer argument, and consolidated documentation.

## What changed

### Employee account settings
- Every signed-in employee may change **their own email** under **Settings → Account security**. Supply the new address twice and the current account password.
- A **single-use, 30-minute** confirmation link goes to the **new** mailbox; the previously verified email remains active until verification completes.
- Confirmation updates the account email, revokes active sessions, and requires another sign-in. Address uniqueness and password checks are enforced by the API; outgoing Gmail/SMTP mail must be configured.
- Existing first-time activation (24-hour verification), forgot-password (30-minute reset), and silent 15-minute idle timeout remain in place.

### Display names versus employee IDs
- **Display-name renaming:** Store admins can rename **themselves** and regular employees with access to their currently selected store, including secondary-store members. They cannot rename **other administrators**. Global admins can rename anyone, including themselves and the original owner. Ordinary employees cannot rename users.
- Display-name updates do not change employee IDs, login credentials, stock attribution or store permissions. Changes appear in the admin audit log.
- **Employee ID renaming:** Only global admins may edit IDs, including their own. The API validates uniqueness and updates related historical attributions, access assignments and authentication references in one transaction, then revokes the renamed employee's sessions. The employee signs in using the new ID and existing password.
- The original `OWNER` account can now be renamed by an authorized global admin, including themselves. Its recovery-owner identity is saved in database settings so global-admin protection and initialization continue after a rename. The original recovery-owner account cannot be demoted.

### Installer and configuration
- On Ubuntu 24.04, use `sudo bash deploy/install.sh --domain your-domain.example` or `--domain=https://your-domain.example`.
- The installer validates an HTTPS public origin, initializes/fixes a missing `PUBLIC_ORIGIN`, preserves other values in the private `.env`, and keeps existing database/Google encryption secrets unchanged.
- You may still provide `PUBLIC_ORIGIN` in the environment, or omit the flag on an existing installation to reuse its saved domain.
- The argument **does not** set up public DNS, TLS certificates, firewalls, reverse proxy or Google OAuth settings.

## Upgrade from v1.1.0

**Back up the production SQL database and the matching private `.env` first.** In particular, retain `POSTGRES_PASSWORD`, `SETUP_TOKEN` and `GOOGLE_TOKEN_KEY`. Review the [Operations guide](../operations.md) and release CI.

```bash
cd /opt/inventory-manager
sudo bash deploy/backup.sh
sudo bash deploy/install.sh --domain zagginventorymanager.com
docker compose --env-file .env -f deploy/compose.yml ps
curl -f http://127.0.0.1:18424/health
```

Replace the domain with **your own domain**, or omit `--domain` to preserve a previously configured `PUBLIC_ORIGIN`. The installer updates your local checkout and rebuilds containers. Publishing this GitHub release **does not deploy** it to the server.

After upgrade, verify:

1. Login with an existing account; inventory and history remain intact.
2. Change an employee's display name with an authorized store admin, and verify that editing another administrator is forbidden.
3. Global admin can rename an employee ID and their own original `OWNER` ID; existing sessions are invalidated and the new ID signs in correctly.
4. Change email and confirm the link in the new mailbox; old address stays active until confirmation.
5. Validate Google callback URL and Gmail sender if changing domains; test password reset, low-stock alerts, check-in/out and the daily backup timer.

## Important safeguards and limitations

- **Initial account claim:** Newly created but unactivated employee IDs can be claimed by whoever registers first. Restrict first-time activation to trusted networks or an identity-aware gateway until that risk is mitigated.
- Passwords remain individual; the retired PIN login is **not** restored.
- Database schema changes may run during startup; reverting the Git commit alone does not reverse schema migrations. Never use `docker compose down -v` or prune volumes as a routine upgrade.
- The original owner identity is tracked after rename, rather than being tied permanently to the literal `OWNER` ID.
- Inspect GitHub CI for this specific tag/commit before production deployment. Perform device/browser acceptance checks and a tested database restore before declaring full production readiness.
