# Inventory Manager v1.0.0 — Initial Release

The first versioned release of the self-hosted Inventory Manager application, including multi-store inventory workflows, a responsive web dashboard, optional Gmail notifications, and full self-hosting documentation.

## Included

- **Inventory:** Product creation/editing, SKU and barcode lookup, camera/USB scanner support, stock receiving/checkout and quantity protection.
- **Multi-store administration:** Store and employee records, per-store permissions, switchable locations and scoped inventory views.
- **History and accountability:** Audit logging, transaction history and editable checkout notes with revision history and attribution.
- **Reporting:** CSV inventory exports, low-stock alerts and reorder lists.
- **Email:** One global Google Gmail API sender, store-specific recipients and queued low-stock notifications.
- **Hosting:** Ubuntu 24.04 installation script, Docker Compose, ASP.NET Core 10 API, PostgreSQL 17, daily SQL backup timer.
- **Independent deployment:** Each new installer supplies **their own public domain** using `PUBLIC_ORIGIN`, **their own Google Cloud OAuth Web application client**, their own hosting and DNS provider.
- **Documentation:** [Complete deployment guide](https://github.com/moordyn/Inventory-Manager/blob/v1.0.0/docs/COMPLETE_DEPLOYMENT_GUIDE.md), [quick installation](https://github.com/moordyn/Inventory-Manager/blob/v1.0.0/docs/deployment.md), and [CHANGELOG](https://github.com/moordyn/Inventory-Manager/blob/v1.0.0/CHANGELOG.md).

## Quick setup

1. Provision an Ubuntu 24.04 server or Proxmox LXC and ensure you can manage HTTPS and your own domain.
2. Download and review the [v1.0.0 installer](https://github.com/moordyn/Inventory-Manager/blob/v1.0.0/deploy/install.sh).
3. On a **new install**, provide your own canonical `PUBLIC_ORIGIN` (`https://inventory.example.com` is a placeholder, **not a usable shared domain**).
4. Point DNS and your HTTPS reverse proxy to the application host on TCP/18424; protect the app port from direct public access.
5. Enroll the one-time installation token, set the administrator PIN and configure stores/employees.
6. **Optional Gmail:** Create your own Google Cloud project and OAuth Web client. Set authorized JavaScript origin to `PUBLIC_ORIGIN` and authorized redirect URI to `PUBLIC_ORIGIN + /api/google/callback`; import the Web client JSON from the global Administration screen and connect your sending account.

For a complete, reproducible walkthrough, follow the [19-chapter installation and operations guide](https://github.com/moordyn/Inventory-Manager/blob/v1.0.0/docs/COMPLETE_DEPLOYMENT_GUIDE.md).

## Release validation

The release workflow is gated behind the repository's GitHub Actions **Inventory Manager CI** job, which builds the .NET API, checks frontend JavaScript and runs PostgreSQL-backed API smoke tests. Publishing the release only means **that CI job passed**; it is not a guarantee that an individual live installation is fully tested.

## Known production-security and operational limits

- **Employee-ID-only logins are not suitable as the sole security barrier on an Internet-facing system.** Require strong additional access control (identity-aware proxy/VPN with MFA) and plan per-user authentication hardening before exposing sensitive business inventory.
- Independently verify domain/HTTPS, reverse-proxy routing, user authorization, physical barcode scanners, mobile camera permissions, and successful sending/receipt of Gmail notifications.
- Verify encrypted offsite backups of PostgreSQL **and** the private `.env`, and perform a restoration drill before treating a deployment as production-ready.
- The system is online-only, not an invoicing/accounting system. History UIs return up to 200 most recent movements.
- OAuth credentials and Gmail tokens belong to the installing business; Google Auth Platform consent-screen status and verification requirements vary by deployment.
- The default installer tracks the repository's `main` branch when cloning/updating. If you need to deploy **exactly** v1.0.0 source rather than whichever code is on `main`, use the tag/archive deliberately and the full guide's migration precautions.

## Upgrades

Before upgrading existing installations, back up PostgreSQL and `/opt/inventory-manager/.env`, review the [deployment guide](https://github.com/moordyn/Inventory-Manager/blob/v1.0.0/docs/COMPLETE_DEPLOYMENT_GUIDE.md), then deploy during a maintenance window. Existing installations are kept on their configured public domain through compatibility migration.

**Source:** GitHub automatically supplies ZIP and tar.gz downloads for the tagged release; no prebuilt desktop/mobile package is part of v1.0.0.
