# Inventory Manager v1.1.0 — Employee passwords and email account recovery

**Inventory Manager v1.1.0** adds individual employee credentials, email verification on first activation, and password reset links. It replaces the previous PIN / employee-ID-only sign-in and removes the visible 30-second sign-out countdown in favor of a **silent 15-minute inactivity limit**.

## What's new

- **Simple admin onboarding:** Administrators continue creating employees with only an Employee ID, name and store. No admin-collected employee email/password required.
- **First-time setup:** Employees provide employee ID, email + confirm email, and password + confirm password. The server validates all entries.
- **Password requirements:** At least 8 characters (up to 128), one uppercase letter, one lowercase letter, one number and one symbol. Hashed with salted PBKDF2-HMAC-SHA256 (600,000 iterations); raw passwords are never stored.
- **Email verification:** A random, single-use link is emailed to the supplied address and expires after 24 hours. The account is activated only after the link is verified.
- **Forgot password:** Enter Employee ID, receive a single-use 30-minute reset link at the **already verified** email, choose a replacement password, and invalidate prior sessions.
- **Session security:** Server sessions expire after 15 minutes without explicit browser user activity, even while automatic inventory refreshes run. The client logs out silently without an onscreen countdown.
- **Global admin security:** OWNER/other global admins use Employee ID + password; Google OAuth import requires re-entering the signed-in global admin's own password.
- **Migration:** Existing products, movements, employee IDs, store grants, checkout notes, and database data remain intact. Legacy sessions are revoked on the first v1.1.0 startup.

## Critical upgrade steps for v1.0.0 installations

**Take a full SQL database backup and save your private `/opt/inventory-manager/.env` before upgrading.** Existing sessions will be revoked once and the old PIN/ID-only logins will no longer work. Schedule a maintenance window, and communicate the activation steps to staff.

1. Back up PostgreSQL and the matching `.env` file, including the original `SETUP_TOKEN` and `GOOGLE_TOKEN_KEY`.
2. Update your Ubuntu deployment using the documented installer: `cd /opt/inventory-manager && sudo bash deploy/install.sh`. The running application is **not** updated automatically by GitHub Release publication.
3. The first time after upgrading, the global **OWNER** completes **Set up your administrator account** using the original **installation token** plus an email address and password entered twice. The old six-digit PIN is not accepted.
4. Log in to the OWNER account with ID and password; the initial OWNER can configure Gmail despite having an unverified bootstrap email. Check that the global sending Gmail/SMTP account is still configured.
5. From **Settings → Account security**, click **Email verification link**, open the link in the OWNER inbox, and confirm. **Forgot password** for the OWNER cannot work until the mailbox is verified.
6. Existing employees open **First-time setup** and register their email/password twice against their original employee ID. They must verify the 24-hour emailed link before their ID + password works.
7. Validate the new 15-minute idle policy, note-edit permissions, store isolation, barcode workflows, low-stock notifications and backup timer.

## New installations

Create your own domain, Ubuntu 24.04 host, reverse proxy/TLS, and own Google Cloud OAuth credentials if enabling Gmail. Follow the [complete 19-chapter installation guide](https://github.com/moordyn/Inventory-Manager/blob/v1.1.0/docs/COMPLETE_DEPLOYMENT_GUIDE.md). On the first admin setup screen, OWNER uses the installer-supplied one-time token to choose an email/password rather than a PIN. Configure and connect a Gmail or SMTP sender before trying to activate ordinary employees, as email delivery is required for verification and recovery links.

## Important security limitation

**Employee ID squatting:** This version deliberately uses unapproved, first-claim employee enrollment. Anyone who knows an existing but unactivated employee ID can attempt to claim it with their own address. A verified email only confirms mailbox possession, not employment identity. For security-sensitive or remote-access deployments, restrict activation to a trusted store network or use an approved identity-aware gateway and additional administrative controls. OWNER alone is protected from this particular unclaimed-account risk by the original setup-token requirement.

Additional limits: email reset cannot be completed when the company mail sender is unavailable; OAuth consent/publishing requirements vary by Google Cloud project; browser/POS scanner/camera and backup restoration must be validated on each live site.

## Tests and source

The v1.1.0 GitHub Actions **Inventory Manager CI** workflow includes the .NET 10 build, frontend checks and PostgreSQL 17 API smoke tests covering owner bootstrap, employee email activation, single-use links, reset and session revocation, stock changes, store permissions and checkout notes. A test-only local email outbox is enabled only under `ASPNETCORE_ENVIRONMENT=IntegrationTest`; production mail uses your own Gmail API sender or configured SMTP.

Source ZIP and tar.gz archives are provided automatically by GitHub for the `v1.1.0` tag. The default Ubuntu installer still pulls `main`; for a fixed tagged version, use the source archive and a controlled deployment, not the moving default branch.
